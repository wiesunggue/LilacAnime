## 서명 설정

이전 워크플로는 고정 signingConfig 없이 `assembleDebug`를 실행했습니다. 임시 GitHub runner가 새 debug.keystore를 만들었으므로 alpha 6과 alpha 7의 인증서가 다릅니다. 소스 수정 여부와 서명키 동일 여부는 별개입니다.

검증 시작점의 저장소에는 기존 서명키 파일이나 재사용 설정이 없었습니다. APK에서 공개 인증서를 확인할 수 있지만, 개인키를 복구할 수는 없습니다. 기존 앱을 삭제하지 말고 설치본에 해당하는 원래 keystore를 확보해야 데이터 유지 업데이트가 가능합니다.

새 워크플로는 키가 없어도 테스트·APK 빌드·서명 유효성 검사를 수행합니다. 다음 GitHub Actions secrets가 모두 설정되고 인증서 지문이 일치할 때만 APK artifact를 게시합니다. 임시 디버그 키로 만든 APK는 검증용이며 게시하지 않습니다.

- `LILAC_ANDROID_KEYSTORE_BASE64`: 기존 keystore 파일의 Base64
- `LILAC_ANDROID_STORE_PASSWORD`: 저장소 비밀번호
- `LILAC_ANDROID_KEY_ALIAS`: 키 별칭
- `LILAC_ANDROID_KEY_PASSWORD`: 키 비밀번호
- `LILAC_ANDROID_CERT_SHA256`: 기존 설치본 인증서 SHA-256 지문

개인키나 비밀번호는 Git에 커밋하지 않습니다. 실제 키를 사용하는 서명 경로는 해당 키가 제공되기 전에는 검증할 수 없습니다.

## 검증의 한계

JVM 테스트·Android 전체 컴파일·APK 서명 검사는 실기기 검증을 대신하지 않습니다. 공급자별 실제 영상·번역 API, UI 조작, Android 서비스의 배터리/백그라운드 정책, Cast·TV 리모컨은 별도 확인이 필요합니다. 모든 버그가 없다고 보장하지 않습니다.
