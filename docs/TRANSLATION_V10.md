# 번역 표시와 테스트 버튼 후속 수정 (2026-11-02)

> 후속 재검증에서 번역 큐 결함 2개를 추가 재현했다. 아래 통과 결과는 안정화 완료를 뜻하지 않는다. [재검증 보고서](SUBTITLE_V10_AUDIT.md)를 먼저 참고한다.

## 참고한 구현과 적용 범위

- [mpv 공식 명령 문서](https://mpv.io/manual/stable/#command-interface): `sub-add`, `sub-reload`로 외부 자막을 읽고 갱신하며 재생 시간·배속·자막 지연·표시를 mpv가 관리한다.
- [sorz/mpv-llm-subtrans](https://github.com/sorz/mpv-llm-subtrans/blob/f0bf8e11cc456333b2d6ece3caf448206f1bc64e/main.lua): 번역 파일이 준비되면 트랙을 추가하고 새 결과가 있을 때 갱신하는 흐름을 참고했다. 코드를 복사하거나 해당 프로젝트의 품질을 보증하는 것은 아니다.
- [libass 공개 API](https://github.com/libass/libass/blob/master/libass/ass.h): 별도 렌더러에서는 이벤트 수명, 재생 시각, 변경 감지와 이미지 상태를 호출자가 관리해야 한다. 이번 앱의 실제 표시 경로에서 별도 오버레이를 제거하여 이중 관리 책임을 줄였다.

## 변경

이전 구현은 원문을 숨긴 뒤 완료된 번역 이벤트만 별도 오버레이에 추가했다. 따라서 네트워크/추론 지연이나 실패로 현재 대사의 번역이 없으면 표시할 대사도 없었다. 즉시 응답을 사용하는 테스트는 이 조건을 충분히 다루지 못했다.

이제 원본 전체 시간표와 완료된 번역을 합친 ASS 스냅샷을 mpv의 자막 트랙으로 전달한다. 미완료/실패한 대사는 원문을 유지한다. **번역이 느려도 모든 대사가 즉시 한국어로 나온다는 의미는 아니다.** 완료된 대사만 한국어로 바뀌며, 원문 대체 규칙을 설정 화면에 표시한다. 원문 모드나 회차/파일 전환 시 원래 파일로 복원한다. 원본 파일을 수정하지 않는다.

ASS의 번역 대상이 아닌 이벤트·주석·스타일도 유지한다. 파일은 원자적으로 기록하고, 내용이 바뀔 때만 갱신한다. 문서 생성은 IO에서 실행하고, 원본 ASS 대사 목록은 한 번만 파싱한다.

테스트 버튼은 별도 진행/결과 창에 성공·실패·시간 초과를 표시한다. 취소와 재시도를 허용하고 늦은 결과의 재적용을 차단한다. 로컬 모델의 실패를 원문 반환으로 감추던 경로와 원문 그대로를 테스트 성공으로 인정하던 예외도 제거했다. 사용자 기기의 실제 원인을 로그 없이 단일 원인으로 확정하지는 않는다.

현재 대사 선택의 250ms 유예 구간도 제거했다. 이전 대사가 끝난 직후로 탐색하고 일시정지하면, 미리 번역을 끈 상태에서 이미 끝난 대사만 번역하고 현재 대사는 영원히 대기하던 결함을 실제 mpv 테스트에서 재현했다.

## 검증

- JVM: 20초 지연에도 전체 대사/시간표 유지, 실패해도 원문 유지, ASS 비번역 이벤트 보존.
- Android UI: 지연 후 성공 표시, API 오류 표시와 재시도, 원문 그대로인 결과 거부, 취소 후 늦은 결과 차단, 시간 초과 표시.
- 실제 mpv: 미완료 원문 표시 → 완료된 한국어 표시 → 미번역 구간 탐색 → 한국어 갱신 → 이전 번역으로 되감기.
- 기존 회귀 검사도 유지한다. 외부 유료 API와 사용자 휴대폰에서 검증한 결과로 표현하지 않는다.
