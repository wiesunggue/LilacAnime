# Android 기능 개선 — 0.4.1-alpha-6

PC의 모든 기능을 이식한 버전은 아닙니다. 실제 사용에서 빠져 있던 자동 동기화, 기기 간 이어보기, 다운로드 관리를 우선 보완했습니다.

| 항목 | 이번 변경 | 검증 범위 |
| --- | --- | --- |
| 자동 기기 동기화 | 연결된 서버에 앱 시작·복귀, 목록·기록 변경, 사용 중 5분 간격으로 동기화. 설정에서 끌 수 있음 | 가상 시간 기반 스케줄·중복 요청·오프라인·재시도 회귀 테스트 |
| 네트워크 복구 | 연결 복구 시 동기화 재개, 통신 장애 시 간격을 늘려 재시도. 인증 오류는 재연결 안내 | 스케줄 및 HTTP 오류 분류 |
| 기기 간 이어보기 | PC 진도(0~100)와 Android 진도(0~1) 변환, 이전 Android 기록 변환, 공급자가 회차 ID를 바꿔도 회차 번호로 연결 | 진도 변환·4/4a 구분·회차 ID 회귀 테스트 |
| 시청 기록 저장 | 재생 중 5초 간격으로 저장. 재생 준비 중 0%로 기존 기록을 덮지 않음 | 코드 및 컴파일 검증; 실기기 프로세스 종료 테스트 필요 |
| 보관함·이어보기 카드 | 동기화된 제목·이미지를 전체 카탈로그를 받기 전에도 표시 | 메타데이터 매핑 테스트 |
| 한 번에 이어보기 | 홈의 이어보기 카드에서 회차를 확인한 뒤 바로 재생. 95% 이상 본 회차는 다음 회차가 있으면 이동 | 진도 정책 테스트 및 컴파일; 실제 스트림은 별도 확인 필요 |
| 작품 소스 선택 | 현재 홈의 소스와 관계없이 선택한 작품의 소스로 상세·회차·플레이어를 연결 | 소스 선택 회귀 테스트 |
| 다운로드 관리 | 설정 → 다운로드 관리: 개별/전체 일시정지, 이어받기, 실패 재시도, 완료 항목 재생, 확인 후 삭제 | 복구 정책 회귀 테스트 및 서비스/화면 컴파일 |
| 일시정지 유지 | 앱 재시작 시 사용자가 멈춘 작업은 자동으로 재개하지 않음. 중단된 진행 작업은 복구 | 복구 정책 회귀 테스트 |
| 자막 포함 이어받기 | 다운로드 요청의 자막 URL·Referer도 보존해 재개 시 사용 | 저장/복구 경로 코드 검토 |

구버전에서 화면에 표시하지 못했던 Miruro·Animenosub·애니24의 서버 항목은 첫 동기화 전에 복원합니다. 지원 범위 확대로 인해 기존 PC 보관함·시청 기록을 삭제로 오인하지 않도록 이관합니다.

## 아직 별도 검증 또는 이식이 필요한 항목

- 모든 영상 사이트의 실제 검색·재생 성공 여부
- 실제 API 키를 사용하는 번역 제공자별 요청과 로컬 AI 성능
- Google Cast, TV 리모컨, 백그라운드/배터리 최적화 환경
- PC의 ffsubsync 음성 분석 기반 자동 자막 싱크와 다음 회차 선행 준비 전체

## 수동 확인 시나리오

1. PC에서 42% 본 회차를 동기화한 뒤 Android의 이어보기 카드와 재생 위치를 확인합니다.
2. Android에서 시청한 뒤 앱을 다시 앞으로 가져와 PC에 진도가 전달되는지 확인합니다.
3. 홈 소스를 바꾼 뒤 다른 소스의 보관함 작품을 열고 해당 소스의 회차가 재생되는지 확인합니다.
4. 다운로드 도중 일시정지하고 앱을 재시작해 멈춘 상태가 유지되는지 확인합니다.
5. 이어받기/실패 재시도로 기존 부분 파일을 사용하는지 확인합니다. URL이 바뀌면 기존 정책에 따라 새로 받습니다.
6. 네트워크를 끊었다가 연결하고 오류 안내 및 자동 동기화 복구를 확인합니다.
