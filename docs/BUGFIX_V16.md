# v16: 번역 요청 폭증·오류 복구·회차 전환 개선 (2026-11-08)

사용자 요청은 자막 외 화면 이동까지 실제로 검사하고, 반복되는 번역·표시·PiP 문제를 개선하는 것이다. APK는 Codex 클라우드에서 직접 빌드한다. 이번 범위는 Android 플레이어/자막/번역 설정/주요 화면 이동이며, 모든 플랫폼과 외부 영상 서버를 검사한 것은 아니다.

## 재현한 결함과 수정

- **실패한 번역의 과도한 요청**: 인증·네트워크 오류에도 묶음 요청을 대사별로 분해하고, 외부 재시도·모델 전환·되감기 초기화가 겹쳤다. 수정 전 코드에 새 검사를 실행해 인증 실패 50대사 창에서 요청 **300회(기대 1회)**, 네트워크 실패 12대사 창에서 **80회(기대 3회)**를 재현했다. 시간은 코루틴 가상 시계로 진행했고 실제 유료 API 요청은 하지 않았다. 이제 오류 형식이 잘못된 모델 응답일 때만 작은 묶음으로 분해한다. 인증 오류는 해당 제공자 요청을 중단하고 일시적 오류의 재시도는 제공자별 3회로 제한한다. 설정된 다른 제공자로의 fallback은 유지하되, 최종 실패하면 사용자가 재시도할 때까지 새 요청을 막는다. 되감기로 재시도 예산이 초기화되지 않는다.
- **DeepL/Gemini/Qwen 중첩 재시도**: DeepL 내부 재시도와 블로킹 대기를 제거했다. Gemini/Qwen은 429/서버 장애 때 모델마다 재시도하지 않는다. 지원되지 않는 모델·요청(400/404)의 모델 전환은 유지한다.
- **실패 후 복구 수단 부재**: 재생 화면에 오류 이유와 `번역 재시도`/`원문으로 계속`을 표시한다. 재시도는 완료된 번역 캐시를 보존한다. 사용자가 일시정지한 영상을 임의로 재개하지 않는다. 자막을 끄면 새 번역 요청과 번역 대기를 멈추며, 이미 전송한 요청까지 취소된다고 보장하지 않는다.
- **다음 회차에서 원문으로 돌아감**: 초기 자막 선택의 기본값을 매번 원문으로 재설정하던 부분을 현재 번역 모드로 유지한다. 이전 회차의 늦은 응답/정리가 새 엔진·자막을 덮어쓰지 않는지 검사한다.
- **변환 자막의 원문 노출**: SBV/MPL2/TTML을 ASS로 변환하는 AI 재생 경로에서 미완료 대사가 원문으로 새던 문제를 수정했다. 수정 전 SBV 재현 검사는 실패했고 수정 후 통과한다. 원문 모드/기존 원문 보존용 스냅샷은 그대로 사용한다.
- **잘못된 응답 표시**: 누락·중복 번호·범위 밖 번호·빈 JSON 번역을 자막으로 표시하지 않는다. 정상 JSON의 순서가 달라도 대사 번호에 맞추며 단일 평문 번역도 지원한다.
- **뒤로가기로 재생 종료**: 모바일에서 플레이어 설정·회차 목록·도움말이 열려 있으면 먼저 닫는다. 실제 설정 화면의 뒤로가기와 그 다음 재생 종료를 검사했다.

v15의 PiP 소유권 수정, 자막 크기·색상 보존, 다음 번역 대기/자동 재개는 계속 포함한다. 번역 상태의 전체 수는 자막의 작업 항목 수이며 HTTP 요청 횟수나 요금으로 해석하면 안 된다.

## 검사 결과

- JVM **126개**, 실패/오류/건너뜀 **0개**. 수정 전 새 회귀 검사 3개의 실패를 보존했다. 단순 결과 문자열 외 재시도 횟수·캐시 보존·숨김 중 요청 중단·원문 노출을 검사한다.
- 실제 Android 검사 최종 집계: **서로 다른 25개 중 최신 결과 24개 통과, 1개 실패(아래 2배속 캡처)**.
- 실제 PlayerScreen/TextureView/libmpv에서 원문↔번역 전환, 초록색 보존, 크기 100→180, 이후 대사 1~5, 되감기 픽셀 일치, 지연 번역 대기/재개, 잘못된 파일 선택 시 기존 자막 유지, 실패→재시도, 숨김→다시 표시, 다음 회차 전환과 이전 응답 차단을 검사했다.
- 실제 MainActivity에서 HOME→PiP→안드로이드 시스템 확대 버튼으로 복귀를 **3회** 반복했다. 같은 엔진·로드 세대·진행하는 재생 위치와 복귀 후 초록색 한국어 픽셀을 확인했다. 상태 값만 바꾸는 별도 수명주기 회귀 검사도 통과했다.
- 실제 번역 설정 버튼·Android Keystore·HTTP·JSON 경로를 로컬 HTTP 서버로 검사했다. DeepL 401은 1회, Gemini 503은 모델 목록 1회+번역 3회 뒤 멈추고 명시적 재시도로 복구했다. 자막 검색 취소/다운로드 중 뒤로가기, 설정 테스트의 오류·재시도·시간 초과·취소도 통과했다.
- **실제 MainActivity의 홈→시청기록→내 목록→설정→다운로드 관리/실패 필터→뒤로→홈을 2회 반복하여 통과했다. 화면 내용과 선택 상태를 확인했다.**
- **기존 2배속/500ms 대사 픽셀 검사는 아직 실패한다. 전체 TextureView 동기 복사를 비동기 PixelCopy의 작은 자막 영역으로 바꾸고 캡처 전후 같은 대사인지 확인하도록 강화했다. 표시 >80/숨김 <20 픽셀, 기대 대사 2~7, 재생 제한 10초를 유지했다. 최종 실패는 `Capture crossed cue 2 at 3800`으로, 2번 대사를 캡처하는 사이 3.8초로 진행했다. 이 환경에서 모든 짧은 대사의 표시를 입증하지 못했다. 정상 속도 PlayerScreen의 이후 대사 1~5 픽셀 검사는 별도로 통과했으며 이 실패를 대체하지 않는다.**

### 실행 이력과 한계

첫 실행은 에뮬레이터의 System UI 응답 없음으로 중단했다. 이것을 앱 자체의 크래시 재현으로 주장하지 않는다. 이후 24개 실행 중 21개 통과/3개 실패였다. 홈 검사는 Material 탭의 장식 아이콘에 없는 contentDescription을 찾았고, PiP 검사는 재생이 시작되기 전에 상태를 조작하거나 시스템 메뉴 조작 대기에서 실패했다. 검사 장치를 보완한 뒤 PiP 두 검사는 통과했다. 앱 APK는 검사 장치 보완 중 변경하지 않았다. 최종 결과는 여러 실행의 최신 결과를 합친 것이며 한 번의 전체 실행이 모두 통과했다고 주장하지 않는다.

API 29 x86_64 소프트웨어 에뮬레이터(KVM 없음)를 사용했다. 반복되는 GMS/System UI ANR을 피하려고 이 작업 소유의 read-only 에뮬레이터에서 Google Play 서비스를 일시적으로 비활성화했다. Google 서비스/Cast 기능, 실제 유료 번역 API·계정별 모델, 사용자 휴대폰/다른 Android 버전, 외부 실스트림·원격 검색/다운로드 성공은 별도 미검증이다. GitHub Actions API는 프록시 CONNECT 403으로 최신 원격 결과를 읽지 못했으며 CI 성공을 주장하지 않는다.
