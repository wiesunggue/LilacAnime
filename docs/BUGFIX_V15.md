# v15: 홈 버튼으로 PiP 진입 후 복귀 시 플레이어 해제 (2026-11-08 한국 시간)

사용자 증상은 홈 버튼으로 영상을 작은 화면으로 만든 뒤 전체 화면으로 돌아오면 앱이 종료되는 것이다.

## 원인과 수정

`PlayerScreen`이 `DisposableEffect`의 키에 PiP 상태를 넣고 있었다. PiP에서 돌아와 상태가 false가 되면 이전 효과의 정리 코드가 실행되어, 화면에 아직 연결된 엔진을 stop/detach/release했다. 화면과 번역 작업은 해제된 엔진을 계속 참조하게 된다.

PiP 상태를 플레이어 소유권 정리의 키에서 제거했다. 창 크기/방향 변경은 별도의 효과가 처리하고, 실제 플레이어 화면 종료 시에 엔진을 정리한다. 엔진 정리는 현재 엔진의 소유권과 백그라운드 오디오 여부를 확인하는 `MpvPlaybackManager`에 맡긴다.

## 검사와 범위

- 수정 전 versionCode 43의 실제 PlayerScreen을 띄워 창 모드 상태를 전환했다. 첫 복귀에서 `PiP restore 0 released the live native player ... was not:<null>`로 실패했다. 이는 화면이 유지되는 동안 실제 엔진이 해제되는 회귀 재현이며, 사용자 휴대폰의 예외 로그를 확보했다는 뜻은 아니다.
- 실제 MainActivity의 홈 버튼 → PiP → 안드로이드 시스템 메뉴의 확대 조작으로 복귀를 3회 반복하는 검사를 추가했다. 같은 엔진과 미디어 로드 세대, 재생 상태·위치, 복귀한 화면 크기와 한국어 초록색 픽셀을 검사한다. 창 모드 상태만 바꾸는 회귀 검사와 구분한다.
- 기존 번역 지연/자동 대기/재개, 자막 크기·색상, 원문↔번역, 후속 대사와 되감기 검사도 유지한다.
- JVM 117개, 실패/오류/건너뜀 0개. 직접 Gradle 앱/Android 테스트 빌드와 기존 서명 검증을 완료했다.
- 최종 Android 결과는 **서로 다른 검사 5개의 최신 결과가 모두 통과**다. 창 모드 상태 회귀와 기존 자막 검사 3개는 전체 실행에서 통과했다. 실제 PiP 검사는 API 29의 접근성 창 정보 누락 및 확대 아이콘의 터치 처리에 맞게 검사 장치만 보완한 뒤 단독 재실행하여 `OK (1 test)`로 통과했다(119.117초). 앱 APK는 이 과정에서 바꾸지 않았다. 초기 전체 실행에 검사 장치 실패 1개가 있었던 사실을 숨기거나 한 번의 전체 실행이 모두 통과했다고 주장하지 않는다.
- KVM 없는 API 29 x86_64 소프트웨어 에뮬레이터를 사용한다. 초기 시스템 PiP 조작 검사에서는 에뮬레이터 System UI 응답 없음이 발생하여 복구했다. 이 실패를 사용자 기기의 앱 크래시 재현으로 바꾸어 표현하지 않는다. 실제 유료 API 및 사용자 기기/다른 안드로이드 버전은 별도 검증 범위다.
