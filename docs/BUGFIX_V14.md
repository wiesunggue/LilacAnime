# v14: 다음 대사에서 원문으로 돌아오는 문제 (2026-11-07 UTC)

사용자는 AI 자막이 표시된 뒤 **다음 대사부터 원문으로 돌아온다**고 확인했다. v13은 미완료 대사를 원문으로 채운 전체 시간표를 mpv에 전달했다. 다음 API 응답이 재생을 따라잡지 못하면 AI 모드에서도 원문을 표시하는 동작이었다. v13의 빠른 대체 응답 검사만으로 이 상황을 해결했다고 볼 수 없었다.

## 변경

- AI 트랙의 미완료 대사에 원문을 넣지 않는다. SRT/VTT/SAMI의 시간표·메타데이터·스타일과 ASS의 스타일·그리기 이벤트는 보존한다. 첫 번역을 준비할 때는 원본 트랙을 유지하며 원본 파일 자체를 수정하지 않는다.
- 재생 위치부터 1초 안에 표시할 대사가 준비되지 않으면 영상을 잠시 멈춘다. 완료된 트랙을 선택한 뒤 자동으로 이어서 재생한다. 미리 번역 옵션을 꺼도 이 최소 구간에 필요한 다음 대사는 요청한다.
- 대기 문구를 항상 표시한다. 번역 실패 시에는 자동으로 원문으로 바꾸지 않고 실패와 대기 상태를 알린다. 사용자는 `원본 그대로` 버튼으로 원문 재생을 선택할 수 있다.
- 자동으로 멈춘 재생만 자동 재개한다. 그 사이 사용자가 일시정지·탐색을 하거나 회차가 바뀌면 이전 작업의 자동 재개 권한을 버린다. 번역을 끄면 해당 번역 작업이 소유한 대기만 해제한다.

## 검증

- 먼저 새 지연 응답 회귀 검사를 v13에 추가하여 다음 원문 대사가 AI 트랙에 들어가는 실패를 재현했다.
- 수정 후 JVM **117개, 실패/오류/건너뜀 0개**. 지연된 다음 대사, 미리 번역 비활성화 상태의 최소 요청 구간, 자동 대기/재개와 사용자 정지·탐색·회차 변경을 포함한다.
- Android의 실제 PlayerScreen/TextureView/libmpv 검사에 다음 대사 응답을 별도 gate로 막는 경우를 추가했다. 번역 대기 문구, 대사 경계 전 정지, 정지 위치 유지, AI 파일에 원문 대사 없음, 응답 후 자동 재개, 이후 대사 1~5의 초록색 픽셀, 되감기를 검사한다. 기존 크기/원문↔번역/ASS 검사도 유지한다.
- 최종 실제 화면 검사 **3개, 실패 0개**, `OK (3 tests)`, 207.912초. APK/Android 테스트 빌드와 기존 키 서명 검증도 통과했다. 검사 캡처와 검증 메타데이터는 다운로드 브랜치에 보관한다.
- 기기는 KVM 없는 API 29 x86_64 소프트웨어 에뮬레이터다. 설치 시 사전 최적화가 오래 걸려 `pm.dexopt.install=extract`를 사용했고, 실제 코드는 Android 런타임에서 실행한다. 기기 성능이나 유료 모델의 응답 속도를 측정하는 검사는 아니다.
- 모델 응답만 대체 제공자를 사용한다. 실제 유료 API·사용자 휴대폰·실스트림은 별도 검증 범위다. 과거 2배속/500ms 대사 캡처 실패는 이 검사로 해결됐다고 주장하지 않는다. 최신 GitHub Actions API 조회는 환경 프록시의 CONNECT 403으로 차단됐다.
